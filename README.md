# Executor Service

Host-native helper service that manages one Docker sandbox, agent execution,
and endpoints for WazzapAgents.

For a deep dive into how the service works end-to-end — request lifecycle,
sandbox architecture, file-sharing contract, skill system, and the agent loop —
see [**ARCHITECTURE.md**](./ARCHITECTURE.md).

## Quick Start

### 1. Environment

Copy the templates and fill in your configuration and API keys:

```bash
cp .env.example .env           # System config (ports, models, LLM_API_KEY)
cp .env.secrets.example .env.secrets  # Skill config/secrets (Brave, 9Router, etc.)
# Edit .env and .env.secrets with your values
chmod 600 .env .env.secrets
```

Both `.env` and `.env.secrets` are git-ignored and loaded by the host service.
Only explicitly allowlisted skill configuration is forwarded to the Docker
sandbox. `LLM_API_KEY` remains host-only because the sandbox runs arbitrary
bash/python/js generated by the LLM. Skill keys are redacted from tool output
and eligible text deliverables; unsafe binary or oversized files containing a
key are rejected.

### 2. Run

Docker Desktop or Docker Engine must be running. Start the API directly on the
host:

```bash
pip install -r requirements.txt
python main.py
```

On startup the service will:
1. Connect to the host Docker daemon.
2. Build or refresh the sandbox image when its source fingerprint changes.
3. Start one local sandbox container on `127.0.0.1:5001`.
4. Bind-mount the host workdir, methods, dependencies, and read-only skills.
5. Start the main Flask service on `:5000`.

## API Contract

### POST /execute

Submit a task to the agent.

**Request:**

```json
{
  "session_id": "user_123_task_abc",
  "instruction": "Extract all tables from /storage/doc.pdf and save each as CSV in /tmp/work_user_123_task_abc/",
  "input_files": [
    "/storage/doc.pdf",
    "/storage/config.json"
  ]
}
```

**Notes:**
- `session_id` — unique identifier for this task
- `instruction` — natural language instruction (agent decides how to approach)
- `input_files` — files are copied atomically into the session workdir. The
  parent may provide an allowed shared path, checksum-verified inline content,
  or a completed resumable `upload_id`; missing/partial staging rejects the
  request instead of starting an agent without its files.

**Immediate Response: `202 Accepted`**

```json
{
  "accepted": true,
  "status": "processing",
  "session_id": "user_123_task_abc",
  "request_fingerprint": "...",
  "requested_file_count": 2,
  "staged_file_count": 2,
  "staged_files": [{"name": "doc.pdf", "size": 1234, "sha256": "..."}],
  "file_errors": []
}
```

---

### GET /sessions/<session_id>/result

Poll for the final result.

**Success Response (`200`)**

```json
{
  "session_id": "user_123_task_abc",
  "success": true,
  "report": "Extracted 3 tables from PDF. Files saved to /tmp/work_user_123_task_abc/",
  "output_files": [
    "/tmp/work_user_123_task_abc/table1.csv",
    "/tmp/work_user_123_task_abc/table2.csv",
    "/tmp/work_user_123_task_abc/table3.csv"
  ],
  "processing_time_sec": 42.5
}
```

**Error Response (`404`) — result not found or expired**

```json
{
  "success": false,
  "report": "Result not found or expired"
}
```

**Important:** Results are **ephemeral** (in-memory only). They are lost when:
- Session idle timeout expires (default: 7200s)
- Service/container is restarted
- WazzapAgents must poll before timeout


## Integration from WazzapAgents

```python
import requests
import time

# 1. Submit task
resp = requests.post("http://localhost:5000/execute", json={
    "session_id": "task_123",
    "instruction": "Extract tables from /storage/doc.pdf and save as CSV",
    "input_files": ["/storage/doc.pdf"]
})
resp.raise_for_status()
data = resp.json()
session_id = data["session_id"]

# 2. Poll for result
for _ in range(60):  # max 60 attempts
    time.sleep(5)
    result = requests.get(f"http://localhost:5000/sessions/{session_id}/result")
    if result.status_code == 200:
        print(result.json())
        break
else:
    print("Timeout polling result")
```

## Session Lifecycle

```
POST /execute
    |
    v
Session created  -->  Agent loop runs (bash/python tools)
    |                       |
    |                       v
    |               end_task called
    |                       |
    |                       v
    |               Result stored in-memory
    |                       |
    |<----------------------+
    |
GET /sessions/<id>/result  <--  WazzapAgents polls
    |
    v
Idle timeout reached  -->  Result deleted + workdir cleaned
```

- Container stays running (long-lived)
- Only session result & workdir are ephemeral

## Methods-first procedural learning

Every new task follows this small persistent-learning loop:

1. Its first tool call inspects regular top-level `.md` and `.txt` files in
   `/methods/` (excluding `README.md`, hidden files, directories, and symlinks).
2. A matching method is used as the starting procedure, then its result is
   objectively validated.
3. If no method matches, or a stored method is stale, the agent falls back to
   the read-only skill catalog in `/skills/` and its normal tools.
4. A missing lightweight Python/Node library or executable may be installed in
   `/dependencies/`, where later sessions discover it automatically.
5. Only after that fallback produces a validated success, the agent atomically
   creates or repairs one reusable method before calling `end_task`.

These directories are live bind mounts of this repository:

| Repository path | Container path | Agent access | Purpose |
|-----------------|----------------|--------------|---------|
| `./methods/` | `/methods/` | read-write | Successful reusable procedures learned across sessions |
| `./dependencies/` | `/dependencies/` | read-write | Persistent Python, Node, executable, and package-cache files |
| `./skills/` | `/skills/` | read-only | Curated reference instructions and tool documentation |

The executor re-applies shared permissions to method documents after every tool
command because each session runs under a different isolated UID. The
`.methods-root` marker makes that permission change fail safely if
`METHODS_DIR` ever points at the wrong directory. Session cleanup never removes
methods because they live outside `WORKDIR_BASE`.

Python packages installed under `/dependencies/python` are injected through
`PYTHONPATH`. Node modules under `/dependencies/node/node_modules` are injected
through `NODE_PATH`. `/dependencies/bin`, Python package scripts, and Node
package scripts are prepended to `PATH`. Package writes are serialized and the
tree receives shared ACL/permission repair so different isolated session UIDs
can reuse it. Downloaded package content is host-persistent but Git-ignored.

This is intentionally a global POC, not tenant-isolated memory: every subagent
can modify the same methods and executable dependencies. Treat both as trusted
operational code, review repository diffs, and never store credentials,
personal data, user content, or untrusted webpage instructions in them. Clear
downloaded dependencies after a Python, Node, OS, or container ABI upgrade if
validation starts failing.

## Environment Variables

Both **`.env`** and **`.env.secrets`** are git-ignored. Keep `LLM_API_KEY` exclusively in **`.env`** because the sandbox runs arbitrary commands generated by the LLM. Put every skill-specific value, including `BRAVE_SEARCH_API_KEY`, `NINEROUTER_URL`, and `NINEROUTER_KEY`, in **`.env.secrets`**. Put any additional custom passthrough secrets there as well.

### Secrets (`.env.secrets`)

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `NINEROUTER_URL` | For 9Router skills | `http://host.docker.internal:20128` in template | Reachable 9Router base URL. A host-local server must listen on an address reachable from Docker, not loopback only. |
| `BRAVE_SEARCH_API_KEY` | No | — | Brave Search API key. Required by the internet-researcher skills. Get one at https://api.search.brave.com |
| `NINEROUTER_KEY` | If 9Router auth is enabled | — | 9Router API key from Dashboard → Keys. Required when `REQUIRE_API_KEY=true`. |

### Config (`.env`)

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `LLM_API_KEY` | Yes | — | LLM API key (e.g. Anthropic, OpenAI) |
| `AGENT_MODEL` | Yes | — | Model name (e.g. `claude-3-5-sonnet`) |
| `AGENT_TEMPERATURE` | No | 0.7 | Sampling temperature |
| `AGENT_MAX_ITERATIONS` | No | 50 | Maximum ReAct turns per task. Set `0` for unlimited iterations. |
| `FLASK_PORT` | No | 5000 | Main service port |
| `EXECUTOR_PORT` | No | 5001 | Localhost port published by the managed Docker sandbox. |
| `EXECUTOR_HTTP_TIMEOUT_GRACE` | No | 15 | Response-delivery grace added after a tool execution timeout. |
| `EXECUTOR_API_TOKEN` | Yes | — | Long random bearer token authenticating host-service tool calls to the sandbox. |
| `EXECUTOR_REQUIRE_AUTH` | No | 1 | Fail startup when executor authentication is required but no token is configured. Set `0` only for loopback-only development. |
| `EXECUTOR_MAX_OUTPUT_BYTES` | No | 4194304 | Combined stdout/stderr cap per tool execution. |
| `EXECUTOR_TOOL_ENV_PASSTHROUGH` | No | `BRAVE_SEARCH_API_KEY,NINEROUTER_URL,NINEROUTER_KEY` | Comma-separated skill variables exposed to tools; service credentials remain blocked. |
| `AGENT_TOOL_RESULT_MAX_CHARS` | No | 120000 | Maximum tool-result characters retained in LLM history; oversized output keeps its head and tail. |
| `SUBAGENT_API_TOKEN` | Remote: Yes | — | Bearer credential for parent calls to execute, steer, status, upload, and output-download endpoints. |
| `SUBAGENT_REQUIRE_API_AUTH` | No | 1 | Require API authentication. Set `0` only for loopback-only development. |
| `SUBAGENT_BIND_HOST` | No | `127.0.0.1` | Host API listen address. |
| `SUBAGENT_WEBHOOK_TOKEN` | Remote: Yes | — | Separate token sent by this service to authenticate callbacks at WazzapAgents. |
| `SESSION_IDLE_TIMEOUT` | No | 7200 | Session result idle timeout (seconds) |
| `LOG_LEVEL` | No | INFO | Logging level |
| `WORKDIR_BASE` | No | `<repo>/.runtime/subagent_work` | Host directory bind-mounted to `/storage/subagent_work` inside the sandbox. |
| `SUBAGENT_STORAGE_DIR` | No | Parent of `WORKDIR_BASE` | Optional host root accepted by the legacy shared-input path. |
| `SUBAGENT_MAX_UPLOAD_CHUNKS` | No | 4096 | Maximum number of chunks accepted for one resumable upload. |
| `SUBAGENT_MAX_ACTIVE_UPLOADS` | No | 1024 | Maximum number of incomplete or unconsumed uploads. |

### 9Router setup

Run 9Router with `REQUIRE_API_KEY=true`, change its initial dashboard password, create a dedicated revocable key in Dashboard → Keys, and configure both `NINEROUTER_URL` and `NINEROUTER_KEY` in `.env.secrets`. For a 9Router process on the Docker host, keep the template URL `http://host.docker.internal:20128`, ensure 9Router listens on an address reachable from the Docker bridge, and do not publish port 20128 broadly to the LAN. For a remote instance, use an HTTPS URL or authenticated tunnel; plain HTTP would expose the bearer key in transit.

The executor deliberately exposes this key to generated skill commands. Redaction prevents accidental echo/file/report leakage; it cannot stop an untrusted generated command from making outbound requests, so use a dedicated revocable key and provider spending limits or quotas where available.

## File Sharing Contract (cross-process)

Shared absolute paths remain the fastest local transport, but they are no
longer required across machines. Small inputs use checksum-verified inline
content; larger inputs use authenticated resumable chunks followed by an
atomic SHA-256/size verification. Large outputs receive an authenticated
same-origin `download_url` with an exact size and checksum. The service returns
a strict per-file acceptance manifest.

When using shared input paths, WazzapAgents and the host service must agree on a
host directory. The host service copies accepted inputs into `WORKDIR_BASE`;
the sandbox mounts only that workdir, never raw parent staging, and isolates
each session under a separate OS identity.

An incorrectly mounted shared directory disables only that fast path; verified
inline/chunk upload and authenticated output download remain available.

The single runtime layout is:

| Concern | Host path | Sandbox path |
|---------|-----------|--------------|
| Accepted input source | `SUBAGENT_STORAGE_DIR` or authenticated upload storage | not mounted |
| Per-session workdir / outputs | `WORKDIR_BASE/<session_id>/` | `/storage/subagent_work/<session_id>/` |
| Learned procedures | `<repo>/methods/` | `/methods/` (read-write) |
| Persistent dependencies | `<repo>/dependencies/` | `/dependencies/` (read-write) |
| Curated skills | `<repo>/skills/` | `/skills/` (read-only) |

`DockerManager` performs the host-path to sandbox-path translation, including
Windows drive paths. `host.docker.internal` is wired into the sandbox so tools
can reach explicitly configured host services such as 9Router. Webhooks are
sent by the host service itself.

## Troubleshooting

### "Docker daemon not available"
- The host service intentionally hard-exits when Docker Engine/Desktop is not running.
- Start Docker, verify the current user can access it, then rerun `python main.py`.

### "Docker build failed"
- Check Dockerfile exists in working directory
- Check disk space

### "Result not found or expired"
- WazzapAgents did not poll fast enough
- Session idle timeout expired
- Fix: increase `SESSION_IDLE_TIMEOUT` or poll more frequently

### Agent returns error / max iterations
- LLM API key invalid or rate-limited
- Instruction too ambiguous for agent to decide tool calls
- Fix: check logs, provide clearer instruction

## Architecture

- `main.py` — Entry point (docker check → build → container start → Flask)
- `src/docker_manager.py` — Docker image and container lifecycle
- `src/session_manager.py` — Ephemeral session tracking & cleanup
- `src/agent.py` — LangChain agent loop with bash/python/end_task tools
- `src/container_client.py` — HTTP client to in-container executor
- `src/executor_server.py` — In-container Flask server for bash/python execution
- `src/prompts.py` — Methods-first policy plus live skill-catalog injection
- `methods/` — Persistent, repository-backed procedures learned after success
- `dependencies/` — Persistent, Git-ignored third-party runtime dependencies
- `src/app.py` — Main Flask app exposing `/execute`, `/health`, `/sessions/.../result`
- `src/config.py` — Environment variable loading & validation
- `src/logger.py` — Structured JSON logging to stdout

## Logging

All logs are structured JSON to stdout:

```json
{"timestamp": "2025-04-24T12:34:56Z", "level": "INFO", "message": "Session xyz started", "session_id": "xyz"}
```

Use `LOG_LEVEL=DEBUG` for verbose tool call logging.
